# Team Management System

A collaborative modular platform developed as part of Software Engineering Lab Experiment 15.

## Project Structure
- `auth.py`: Authentication and authorization module.
- `user_module.py`: Team member and profile management.
- `task_module.py`: Task assignment and milestone tracking.

## Git Branching Strategy & Workflow
Our team follows the GitHub Flow branching model:
1. **`main` Branch**: Contains production-ready code. Direct commits to `main` are restricted.
2. **Feature Branches**: Every feature or bugfix is developed on a dedicated branch named `feature-<module-name>` (e.g. `feature-auth-module`, `feature-tasks`).
3. **Pull Requests & Code Reviews**: 
   - A pull request (PR) must be submitted to merge a feature branch into `main`.
   - At least one team member must review and approve the diff.
4. **Merge Conflict Resolution**:
   - Conflicts must be resolved using IDE merge tools (e.g., VS Code 3-Way Merge Editor) before completing PR merge.
